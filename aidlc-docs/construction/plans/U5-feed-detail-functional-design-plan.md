# U5 feed-detail — 기능 설계 계획

**Unit 범위** (unit-of-work.md): API `GET /api/feed`·`GET /api/notices/[id]`(S4), 피드(C26), 공고 상세(C27: 일정·세대수·판정 이유·AI 요약·원문·캘린더), 관심 공고(C28)
**주 스토리**: US-12·13·14·15·16·17 (기여: US-11 — 알림을 눌렀을 때 열리는 화면 `/notice/[id]`·`/`, 계약 K8)
**이미 정해진 것**
- 노출 조건 `isVisible`(U2 BR-U2-59): 미충족 숨김, 관심 지구만, 마감 제외. 알림(U6)도 같은 정의를 씀
- 판정은 U2가 `judgements`에 미리 저장함(verdict·in_district·score·detail). 피드는 계산하지 않고 읽기만 함(AD-3)
- 사유 문구에는 내 금액이 없음. 화면이 기기 프로필에서 붙임(NFR-U2-10, `userValue`)
- 접수 상태 `noticeStatus`: 마감일이 지나면 closed, 시작일이 지나면 open, 그 밖은 upcoming(마감일이 없으면 닫히지 않음)
- AI 요약 형식(U3): `eligibilityPlain`, `forSeniorCouple`, 상태 pending·done·failed
- 원문 주소: `source_notices.original_url` (같은 공고가 여러 기관에 있으면 여러 개)
- 기기 저장 키 `mz.bookmarks`(U4가 자리만 잡음), 하단 메뉴의 "관심 공고" 자리(U1)

**원칙**: 놓치지 않기, 큰 글씨·큰 버튼, 알림 → 상세 → 원문 2탭 이내
