# U5 feed-detail — 변경 요청 4 기능 설계 계획 (뒤로 버튼)

> 근거: requirements.md §11 (C4-D6, FR-C4-15·16, NFR-C4-4), change-4-execution-plan.md
> 기존: `src/features/app-chrome/BackNavigation.tsx`·`back-target.ts` (2026-10-17 요청으로 만든 규칙)

## 지금 구조와 문제 (코드 분석)

- 앱 안 이동은 모두 `replace` — 방문 기록이 쌓이지 않고, 뒤로 버튼은 화면 위계로 움직인다(`backTarget`). 이 규칙은 그대로 둔다
- 뒤로 버튼을 받는 길이 둘이고, 브라우저에 따라 **하나만** 쓴다:
  1. `CloseWatcher`가 있으면(Android Chrome 120+) 그것만 — 방문 기록 지킴이는 넣지 않는다
  2. 없으면(삼성 인터넷 등) 방문 기록 **지킴이 한 칸**을 앱을 열 때 넣고 `popstate`로 받는다
- 사용자 신고: 상세에서 뒤로 → 바로 종료 = **뒤로 버튼을 앱이 전혀 받지 못함** (받았다면 목록으로 갔다)
- 원인 후보
  - 길 2: 지킴이를 **사용자 조작 전**(앱을 연 직후)에 넣는다. Chrome 계열은 사용자 조작 없이 넣은 방문 기록을 뒤로 버튼이 건너뛰게 한다(방문 기록 조작 방지) → 첫 뒤로 버튼이 지킴이를 건너뛰어 앱이 닫힌다. 지금 코드는 지킴이가 "빠졌을 때"만 터치 때 다시 넣고, "들어 있지만 건너뛰어지는 칸"은 고치지 못한다
  - 길 1: 휴대폰의 실제 뒤로 버튼으로 시험한 적이 없다 — E2E는 Esc 키로만 시험한다
- 설치 브라우저: 모름 (Q1) → **두 길 모두에서 동작**하게 만든다

## 이번에 바꾸는 것

1. 두 길을 **함께** 쓴다: CloseWatcher가 있으면 켜 두고, 방문 기록 지킴이도 항상 둔다 — 뒤로 버튼 신호는 둘 중 하나만 받는다(창이 닫히면 방문 기록은 움직이지 않는다)
2. 지킴이는 **사용자 조작을 처리하는 중에만** 넣는다(터치·키·클릭) → 건너뛰기 대상이 되지 않는다. 앱을 연 직후 조작 전에는 CloseWatcher가 지킨다
3. 종료 안내: "종료하시려면 뒤로가기 버튼을 한번 더 클릭해주세요." **3초**. 안내 중에는 아무것도 받지 않게 지킴이를 조용히 빼고(CloseWatcher도 끔) → 두 번째 뒤로 버튼은 그대로 앱을 닫는다
4. 판단 로직을 화면 코드에서 떼어 **순수한 상태 기계**로 만들어 테스트한다. E2E는 실제 방문 기록 뒤로(`page.goBack`) 길도 시험한다
5. 실제 휴대폰 확인은 Build and Test (NFR-C4-4)
