## 질문

### Q1. 프로필을 저장할 때 판정 재계산을 언제 할까요? (성능)

A) **저장 요청 안에서 바로**: 저장 → 재계산(1초 이하, NFR-U2-02) → 응답. 응답이 오면 피드가 이미 새 판정을 보여줌 (US-18 "바로 바뀐다") **(추천: 규모가 작아 가장 단순)**

B) 저장만 하고 응답한 뒤, 서버가 뒤에서 재계산 (Vercel `after`). 화면은 잠시 뒤 피드를 다시 불러옴

X) 기타 (아래 [Answer]: 태그 뒤에 설명해 주세요)

[Answer]: A

### Q2. 프로필은 저장됐는데 재계산이 실패하면? (복원력)

A) **저장은 성공으로 응답**하고 "판정은 잠시 후 반영돼요"라고 알려 줌. 실패를 기록하고, 다음 날 새벽 전체 재계산(또는 다음 저장) 때 다시 계산됨. 기존 판정은 그대로 둠 **(추천: 입력한 정보는 잃지 않음)**

B) 저장 전체를 실패로 응답(트랜잭션으로 묶음)하고 다시 시도하게 함

X) 기타 (아래 [Answer]: 태그 뒤에 설명해 주세요)

[Answer]: A

### Q3. 두 재계산이 동시에 돌 때 오래된 결과가 새 결과를 덮어쓰지 않게 하려면? (복원력)
예: 새벽 전체 재계산이 기기 A의 **옛 프로필**을 읽은 직후, 사용자가 프로필을 고쳐 저장·재계산했다. 그 뒤 새벽 작업이 옛 프로필로 계산한 판정을 저장하면 **새 판정이 옛 판정으로 덮어써진다**.

A) **프로필 버전 확인**: 판정 저장 DB 함수가 "계산에 쓴 프로필 버전 ≥ 현재 저장된 프로필 버전"일 때만 저장하고, 아니면 건너뜀(최신 판정 보호). 이미 있는 `profileVersion` 값을 활용 **(추천)**

B) 기기별 잠금: 한 기기의 재계산은 한 번에 하나만 실행 (DB advisory lock)

C) 대응하지 않음: 다음 날 전체 재계산 때 바로잡힘

X) 기타 (아래 [Answer]: 태그 뒤에 설명해 주세요)

[Answer]: A
