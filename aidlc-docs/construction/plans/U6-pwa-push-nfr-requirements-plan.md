# U6 pwa-push — 비기능 요구사항 계획

**대상**: 매시 발송 `dispatch`(Edge Function), 구독·시험 알림 API(Next), 서비스워커·설치(브라우저)
**이미 정해진 것**
- 실행 환경: Supabase Edge Function(Deno) + pg_cron, Next(Vercel) API, Supabase 무료 플랜 (NFR-5.1)
- 호출 보호: U3와 같은 비밀 헤더(Vault의 `cron_secret`) 방식 (BR-U6-93)
- 재실행 안전: 하루 몫을 먼저 잡고 알림 기록은 유일 (BR-U6-21·24)
- 테스트: Vitest + fast-check(PBT), Playwright + axe, pgTAP (U1 PBT-09 결정)
- 가족 몇 명이 쓰는 비공개 앱 (기기 수 수십 이하 예상)

### Q1. 웹 푸시 보내기 구현 방법
웹 푸시는 알림 내용을 표준 방식(RFC 8291)으로 암호화하고, 서버 신분(VAPID, RFC 8292)을 서명해서 보냅니다. 매시 발송은 Deno(Edge Function), 시험 알림은 Node(Next)에서 보냅니다.

A) **공용 코드(`_shared`)에 브라우저 표준 암호 기능(Web Crypto: ECDH·HKDF·AES-GCM·ECDSA)으로 직접 구현**. Deno·Node가 같은 코드를 씀. 표준 문서의 공식 시험 값(RFC 8291 부록 A)과 똑같이 나오는지 테스트로 고정. 새 라이브러리 없음 **(추천)**

C) 양쪽 모두 `npm:web-push` (Deno의 Node 호환 기능에 기댐 — Edge에서 동작이 불확실)
