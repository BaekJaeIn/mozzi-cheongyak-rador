## 질문

### Q1. 같은 공고가 여러 소스에 나올 때 (중복 처리)
예를 들어 LH 공공분양이 청약홈과 마이홈에 둘 다 올라올 수 있습니다. 스키마의 공고 식별 방식을 정해야 합니다.

A) **소스별로 따로 저장하고, 대표 공고로 묶음**: 원천은 `소스+공고번호`로 따로 저장하고, 같은 공고로 판단되면(단지명·모집공고일·공급기관이 같음 등) 하나의 **대표 공고**로 묶어 피드·알림에는 대표만 보여줌. 묶는 규칙은 U3에서 확정 **(추천: 알림 수가 부풀지 않음)**

B) 소스별로 따로 저장하고 그대로 모두 보여줌 (가장 단순, 같은 공고가 두 번 보일 수 있음)

X) 기타 (아래 [Answer]: 태그 뒤에 설명해 주세요)

[Answer]: A

---

### Q2. 마감된 공고와 관련 데이터는 얼마나 보관할까요?
마감된 공고는 피드에서 빠지지만, 관심 공고(북마크)와 링크로 상세를 볼 때는 필요합니다.

A) **공고는 계속 보관**하고, 마감된 공고의 판정 결과(`judgements`)만 마감 후 30일이 지나면 삭제 **(추천: 데이터가 작아 보관 부담 적음)**

B) 공고와 판정 모두 마감 후 1년이 지나면 삭제

C) 아무것도 삭제하지 않음

X) 기타 (아래 [Answer]: 태그 뒤에 설명해 주세요)

[Answer]: B

---

### Q3. 오래 쓰지 않는 기기의 정보는 어떻게 할까요?
휴대폰을 바꾸거나 브라우저 데이터를 지우면 기기 토큰이 사라져서, 서버에는 주인 없는 프로필(소득·자산 포함)이 남습니다.

A) **마지막 접속 후 180일**이 지나면 그 기기의 프로필·구독·판정·알림 이력을 자동 삭제 **(추천)**

B) 1년이 지나면 자동 삭제

C) 자동 삭제하지 않음 (직접 "모두 지우기"를 눌러야만 삭제)

X) 기타 (아래 [Answer]: 태그 뒤에 설명해 주세요)

참고: "마지막 접속"은 앱을 열어 서버에 요청한 시각입니다. 알림만 받고 앱을 열지 않는 날은 접속으로 세지 않습니다.

[Answer]: A

---

### Q4. 처음 기기를 등록할 때 아무나 등록할 수 있게 할까요?
앱 주소를 아는 사람은 누구나 기기를 등록하고 정보를 저장할 수 있습니다. 가족만 쓰는 비공개 앱입니다(R2).

A) **가족 코드 입력**: 처음 실행할 때 미리 정한 짧은 코드(서버 환경 변수)를 한 번 입력해야 등록됨. 부모님께는 자녀가 알려 드리거나 첫 설치 때 함께 입력 **(추천)**

B) 누구나 등록 가능 (가장 단순)

C) 누구나 등록 가능하되, 같은 IP에서 짧은 시간에 여러 번 등록하면 막음

X) 기타 (아래 [Answer]: 태그 뒤에 설명해 주세요)

[Answer]: B

---

### Q5. 기기 토큰이 사라졌을 때 (브라우저 데이터 삭제, 휴대폰 교체)

A) **새 기기로 처음부터**: 새 device_id로 등록하고 마법사를 다시 진행. 이전 기기 데이터는 Q3 규칙으로 정리 **(추천: 로그인 없음(D11)과 일관)**

B) 복구 코드: 설정 화면에 복구 코드를 보여주고, 새 기기에서 입력하면 이전 프로필을 가져옴 (기능이 하나 더 생김)

X) 기타 (아래 [Answer]: 태그 뒤에 설명해 주세요)

[Answer]: A
