## 질문

### Q1. `analyze`가 동시에 두 번 돌 때 같은 공고를 두 번 처리하지 않게 하려면? (NFR-U3-09)
예: 앞 실행이 느려 다음 시간 실행과 겹치거나, 개발자가 수동으로 한 번 더 실행한 경우.

A) **공고 단위 예약(claim)**: DB 함수가 대기 공고를 `for update skip locked`로 골라 `ai_claimed_at = 지금`을 표시하고 돌려줌. 다른 실행은 표시된 공고를 건너뜀. 실행이 중간에 죽으면 **10분 뒤** 예약이 풀려 다시 처리 가능 **(추천: 겹쳐도 각자 다른 공고를 처리)**

B) 실행 단위 잠금: `analyze` 전체를 DB advisory lock으로 한 번에 하나만 (겹치면 뒤 실행은 바로 종료)

X) 기타 (아래 [Answer]: 태그 뒤에 설명해 주세요)

[Answer]: A

### Q2. 이미 AI 처리가 끝난 공고가 바뀌면(정정 공고), 다시 분석될 때까지 무엇으로 판정할까요?
`collect`가 내용 변경을 감지하면 공고는 다시 `pending`이 되고, `analyze`가 처리할 때까지 최대 몇 시간 걸립니다.

A) **표준 요건으로 되돌림**: 바뀐 공고는 예전 추출 결과를 버리고 표준 요건으로 판정(대부분 "확인 필요"), 재분석 후 정밀 판정. 예전 요약은 남기되 "공고가 바뀌어 다시 확인 중이에요" 표시 **(추천: 바뀐 공고를 옛 기준으로 판정하지 않음)**

B) 예전 추출 결과를 그대로 유지하다가 재분석 후 교체 (판정이 계속 정밀하지만, 정정 내용이 반영되기 전까지 틀릴 수 있음)

X) 기타 (아래 [Answer]: 태그 뒤에 설명해 주세요)

[Answer]: A
