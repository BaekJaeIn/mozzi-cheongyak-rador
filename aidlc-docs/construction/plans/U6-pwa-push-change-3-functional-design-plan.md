## 설계 메모 (질문 아님)

- **모든 가구에 적용**(FR-C3-15): 부모님 휴대폰도 별표한 공고가 있으면 마감 임박 알림이 함께 온다(US-26 "새로 함께 온다, 끌 수 있다")
- **판정·관심 지역과 상관없이** 별표한 공고면 알린다 — 별표는 사용자가 직접 고른 것. 마감이 지난 공고·지워진 공고는 대상 아님
- **서버에 보내는 것은 공고 ID뿐**(개인 정보 아님). 기기 ID와 묶여 저장되고, 모두 지우기·기기 삭제 때 함께 지운다
- **하루 1번 그대로**: 새 공고와 마감 임박이 같은 날이면 한 알림에 합친다. 마감 임박만 있어도 그날 알림 1번으로 보낸다(지금은 새 공고가 없으면 보내지 않음 — 이 경우만 달라짐)
- **같은 공고 마감 알림은 한 번**: 마감 알림 기록을 알림 기록과 같은 표에 종류를 달리해 남긴다(`kind = deadline`) — 실패·재시도·여러 날 대상이어도 한 번
- 앱 기존 관심 공고(기기에만 있던 별표)는 업데이트 뒤 앱을 처음 열 때 한 번 서버로 보낸다(부모님 휴대폰의 별표도 바로 대상이 됨)

## Question 2 — 새 공고 알림과 겹치면 문구는?

A) **한 알림에 두 줄.** 본문 첫 줄 = 지금 문구(새 공고), 둘째 줄 = "관심 공고 ○○ 마감이 내일이에요"(2건 이상이면 "관심 공고 2건 마감이 내일이에요"). 마감 임박만 있으면 그 한 줄만. 누르면: 새 공고가 있으면 지금처럼(1건 → 상세, 여러 건 → 피드), 마감 임박만 1건이면 그 상세, 2건 이상이면 관심 공고 화면 **(추천 — 알림 1번에 둘 다 보이고, 새 공고 알림 동작은 그대로)**

B) 마감 임박이 있으면 마감 임박을 앞에, 새 공고는 "그 밖에 새 공고 N건"으로 뒤에

## Question 3 — 관심 공고 ID는 언제 서버에 보낼까요?

A) **별표를 누를 때마다 바로, 목록 전체를 덮어쓰기로 보낸다**(`PUT /api/bookmarks { ids }`). 기기 저장이 먼저이고, 보내기 실패는 앱을 다시 열 때 다시 보낸다(내 정보 저장과 같은 방식). 별표 화면에는 영향 없음 **(추천 — 서버가 항상 기기와 같아지고, 전체 덮어쓰기라 순서가 꼬여도 마지막 값이 맞다)**

B) 앱을 열 때만 한 번 보낸다 (별표한 날 바로 마감 알림이 필요하면 늦을 수 있다)
