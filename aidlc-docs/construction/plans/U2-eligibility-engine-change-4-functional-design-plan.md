# U2 eligibility-engine — 변경 요청 4 기능 설계 계획 (지역·대상 거르기)

> 기존 설계: `U2-eligibility-engine/functional-design/` (§11까지 변경 3)

## 지금 구조 (확인한 것)

- 노출 = 판정이 미충족 아님 + `inDistrict` + 마감 전 (`isVisible`, 피드·알림 공용)
- `inDistrict` = 관심 지구 겹침 **또는** 관심 시·군과 공고 지역이 맞음 (`regionMatches`). 공고 지역이 시·도까지만이면 그 시·도의 모든 관심 시·군과 맞음 (BR-U2-C11 ②)
- 공급유형은 주택형마다 1개. 제목에 "행복주택"만 있어도 `happy_senior`(행복주택 — 어르신 몫), "국민임대"만 있어도 `national_rental_senior`
- 신혼 가구: `happy_senior`·`national_rental_senior` → "신혼부부 몫 임대"로 판정. `other` → 일반공급, 분류 못 함 → 확인 필요
- 공고 단위의 "신청 대상"(기숙사·창업자 등) 개념은 없다

## 이번에 바꾸는 것

1. **관심 지역**: BR-U2-C11 ② 삭제 — 공고가 시·도까지만이면 관심 시·도 **전체**를 고른 경우에만 맞음 (C4-D2)
2. **공고 신청 대상** `audiences`(공고 단위 집합, U3가 채움)와 **가구 종류 × 대상** 표 (C4-D3, FR-C4-10·12)
3. **행복주택·국민임대 계층 모름** 분류 (FR-C4-13)
4. 노출은 기존 `isVisible` 그대로 — 대상이 막히면 판정이 미충족이 되게 해서 피드·알림이 같이 따른다 (FR-C4-14, Q1)

## Question 1 — 대상이 맞지 않는 공고는 판정을 어떻게 남길까요?

A) **판정을 "미충족"으로 하고 이유를 남긴다.** 예: "기업체 기숙사 공고예요. 회사가 직원을 위해 신청해요". 피드·알림에서는 빠지고, 이미 별표한 공고라면 관심 공고·상세에서 이유를 볼 수 있다. 피드·알림의 노출 코드는 그대로 **(추천 — 지역 밖·마감처럼 "왜 안 보이는지"가 남는다)**

## Question 3 — 제목에 "행복주택"·"국민임대"만 있고 계층을 모르는 주택형은요?

A) **"계층 모름" 공급유형을 따로 둔다** — 이름 "행복주택 (계층은 공고문 확인)", "국민임대 (계층은 공고문 확인)".
- 부모님(노부부) 판정 요건은 지금 어르신 몫과 같게 둔다 → **부모님 판정 결과는 그대로**, 이름만 바뀐다
- 신혼 가구는 지금처럼 "신혼부부 몫 임대"로 판정
- 공고문에서 **고령자 계층으로 확인된** 주택형(`happy_senior`·`national_rental_senior`)은 신혼 가구에 미충족("어르신 몫이에요") **(추천)**

B) 코드는 그대로 두고 화면 이름만 "행복주택"으로 바꾼다 (신혼 가구는 고령자 계층으로 확인된 주택형도 지금처럼 신혼 몫으로 판정)
