# U6 pwa-push — 기능 설계 계획

**Unit 범위** (unit-of-work.md): 홈 화면 설치(manifest·서비스워커·Android 설치 창·iPhone 그림 안내), 알림 권한·구독(`POST /api/push/subscribe`), 매시 발송 Edge Function `dispatch`(대상 선정 C14·발송 C15·알림 기록 C16), 알림 클릭 이동, 열린 이슈 OI-5
**주 스토리**: US-01 설치, US-03 알림 허용, US-10 하루 1번 알림, US-11 알림 눌러 바로 보기
**이미 정해진 것**
- 테이블: `push_subscriptions`(endpoint 기본키, 기기별 여러 개 가능), `notification_log`(기기 × 공고 기본키 — 같은 공고는 두 번 기록되지 않음) — U1
- 노출 조건 `isVisible`(U2 K5): 피드와 알림이 같은 함수를 쓴다 (US-10 "피드와 똑같다")
- 알림 시각·켜기/끄기: `devices.notify_hour`(기본 9시)·`notify_enabled`, 설정 화면(U4)
- 수집은 매일 KST 05:00, 0~4시 알림은 전날 수집분 기준 (OI-4, U3)
- U4의 알림 연결 자리 `setPushPort`(마법사 알림 단계·설정의 알림 켜기), U5의 이동 경로 `/notice/[id]`·`/`(K8)
- 마감임박 별도 알림은 1차 범위 밖 (FR-11.6)

아래 **질문 11개**의 `[Answer]:` 뒤에 보기 알파벳을 적고, 저장한 뒤 "완료"라고 알려 주세요. **(추천)**은 제 의견입니다. 추천대로 하실 거면 "모두 추천대로"라고만 하셔도 됩니다.
