# U4 profile-settings — 업무 규칙

> 근거: 계획 답변 Q1~Q10 = 모두 A (2026-10-15), stories US-02·04~09·18~20, U2 domain-entities §1·§8, U2 BR-U2-72·73, U1 BR-U1-09·10·20
> 프로필 항목·형식 검증은 U2 `validateProfile`이 기준이다. 이 문서는 **입력 방식·건너뛰기·저장·동기화·삭제·화면 모드** 규칙을 정한다.

---

## 1. 처음 실행 (US-02)

| ID | 규칙 |
|---|---|
| BR-U4-01 | 기기에 **저장된 프로필이 없으면** 홈(`/`)은 피드 대신 처음 실행 안내를 보여 준다: 제목 "내 정보를 넣으면 맞는 공고만 골라 드려요", 설명 3줄(① 3기 신도시 공고를 매일 모아요 ② 우리 집 조건에 맞는지 확인해요 ③ 새 공고가 있으면 하루 1번 알려 드려요), 버튼 **[시작하기]** 하나 |
| BR-U4-02 | 저장된 프로필은 없고 **입력 중이던 초안**이 있으면 홈을 열 때 마법사의 그 화면으로 바로 간다 (Q10=A). 마법사 위에 작게 [처음부터 다시] |
| BR-U4-03 | 처음 실행 안내와 마법사에서는 아래 메뉴(하단 내비게이션)를 숨긴다. 피드·관심 공고는 프로필이 있어야 의미가 있어서다 |
| BR-U4-04 | 기기 등록(U1 `ensureDevice`)은 처음 실행 화면을 보여 주기 전에 끝난다. 첫 등록이 실패하면 U1 "다시 시도" 화면을 그대로 보여 준다 (코드 생성 계획에서 조정 — U1 승인 동작 유지, 첫 실행은 인터넷이 있는 상황) |

## 2. 마법사 화면 (Q1=A)

한 화면에 질문 1~2개. 답에 따라 필요 없는 화면은 건너뛴다. 화면 위에 **그룹 이름 + 진행 표시**("주택·통장 7/16"). 분모는 **지금 답으로 보일 화면 수**이고, 답이 바뀌면 다시 센다.

| # | 화면 ID | 그룹 | 질문 | 보이는 조건 | 저장 항목 |
|---|---|---|---|---|---|
| 1 | `selfBirth` | 기본 | "이 휴대폰을 쓰시는 분의 생년월일" | 항상 | `self.birthDate` |
| 2 | `household` | 기본 | "주민등록에 함께 올라 있는 분은 누구인가요?" 부부 두 분만 / 혼자 / 다른 가족도 함께 | 항상 | `householdType` |
| 3 | `householdMore` | 기본 | "함께 올라 있는 가족은 모두 몇 명인가요?(본인 포함)" 2~8 + "그중 배우자가 계신가요?" 예/아니오 | `householdType = other` | `householdSize`, 배우자 유무 |
| 4 | `spouseBirth` | 기본 | "배우자분의 생년월일" | 배우자 있음 | `spouse.birthDate` |
| 5 | `head` | 기본 | "주민등록상 세대주는 누구인가요?" 나 / 배우자 / 다른 가족 / 잘 모르겠어요 | 항상 (배우자 없으면 "배우자" 보기 없음) | `householdHead` |
| 6 | `residence` | 거주 | "지금 사시는 곳" 시도 → 시군구 | 항상 | `residence.sido`, `residence.sigungu` |
| 7 | `residenceYears` | 거주 | "그곳에 사신 지 얼마나 되셨나요?" | 시도를 골랐음 | `residence.years` |
| 8 | `homeOwned` | 주택 | "지금 집을 가지고 계신가요? (부부 모두 포함)" 예 / 아니오 / 잘 모르겠어요 | 항상 | `housing.homeless` (예 → false) |
| 9 | `homeCount` | 주택 | "가지고 계신 집은 몇 채인가요?" 1·2·3·4·5채 이상 | 집 있음 | `housing.ownedCount` |
| 10 | `homelessYears` | 주택 | "집 없이 지내신 지 얼마나 되셨나요?" | 집 없음 | `housing.homelessYears` |
| 11 | `savingsHas` | 통장 | "청약통장이 있으신가요?" 예 / 아니오 / 잘 모르겠어요 | 항상 | `savings.has` |
| 12 | `savingsKind` | 통장 | "어떤 통장인가요?" (4종, 이름 + 쉬운 설명) | 통장 있음 | `savings.kind` |
| 13 | `savingsPeriod` | 통장 | "가입하신 지 얼마나 되셨나요?" + "몇 번 넣으셨나요?" | 통장 있음 | `savings.months`, `savings.paymentCount` |
| 14 | `savingsAmount` | 통장 | "통장에 들어 있는 돈(납입 인정 금액)" | 통장 있음 | `savings.depositManwon` |
| 15 | `income` | 소득·자산 | "부부 두 분의 소득을 합친 월평균(세금 떼기 전)" | 항상 | `money.monthlyIncome` |
| 16 | `spouseEarns` | 소득·자산 | "배우자분도 일하거나 사업 소득이 있나요?" | 배우자 있음 | `money.spouseEarns` |
| 17 | `asset` | 소득·자산 | "세대 전체의 총자산(집·땅·예금·주식 등)" | 항상 | `money.totalAsset` |
| 18 | `car` | 소득·자산 | "가지고 계신 자동차 값(여러 대면 합계, 없으면 0)" | 항상 | `money.carValue` |
| 19 | `welfare` | 소득·자산 | "아래 중 해당하는 것이 있나요?" | 항상 | `welfare` |

| 22 | `tenurePrefs` | 선호 | 분양 / 임대 / 둘 다 + 저층 선호 예 / 상관없음 | 항상 | `prefs.tenure`, `prefs.lowFloor` |
| 23 | `review` | 확인 | 그룹별 요약 + [고치기] + [저장] | 항상 | — |
| 24 | `notify` | 알림 | 알림 소개 + [알림 받기] / [나중에] | 저장 직후 (처음 입력할 때만) | — (U6) |

| ID | 규칙 |
|---|---|
| BR-U4-10 | 보이는 화면 순서는 위 표 순서 그대로이고, 보이는 조건은 **지금까지의 답**으로만 정한다 |
| BR-U4-11 | 모든 화면에 큰 **[이전] / [다음]**. 첫 화면의 [이전]은 처음 실행 안내로 돌아간다 |
| BR-U4-12 | 답을 바꿔 어떤 화면이 **안 보이게 되면, 그 화면의 답은 지운다**(저장 때 `null`). 예: 부부 → 혼자로 바꾸면 배우자 생년월일·배우자 소득을 지우고, 세대주가 "배우자"였으면 비운다 |
| BR-U4-13 | `householdType` → `householdSize`·`spouse`: 부부 두 분만 → 2명·배우자 있음, 혼자 → 1명·배우자 없음, 다른 가족도 함께 → 화면 3에서 고른 수(2~8)·배우자 유무 |
| BR-U4-14 | **"본인·배우자"는 이 휴대폰 사용자 기준**이라는 것을 화면 1·4·5에 문구로 알린다 (P2: 어머니 기기에서는 어머니가 "나") |
| BR-U4-15 | 화면 22의 저층 선호 "상관없음" = `lowFloor: false` |
| BR-U4-16 | 화면 24(알림)는 U6의 알림 구독 기능과 연결한다. 이 기기 브라우저가 알림을 지원하지 않으면 "이 휴대폰에서는 알림을 켤 수 없어요" 안내 후 [다음]으로 피드로 간다 |

## 3. 입력 방식·검증

### 3.1 생년월일 (Q2=A)

| ID | 규칙 |
|---|---|
| BR-U4-20 | 연·월·일을 각각 드롭다운(휴대폰 기본 선택 휠)에서 고른다 (2026-10-17 사용자 요청으로 변경). 연도: **본인 1930~1975년**(처음 위치 1960년), **배우자 1930년~(올해−19)년**(배우자가 더 젊을 수 있어서, 처음 위치 1960년) |
| BR-U4-21 | 일 목록은 고른 연·월에 맞춘다 (2월 28/29일, 30·31일). 연·월을 바꿔 날짜가 없어지면 그 달 마지막 날로 맞춘다 |
| BR-U4-22 | 셋 다 고르면 바로 "**만 66세**"를 크게 보여 준다 (U2 `ageAt`, 기준일 = 오늘 KST) |
| BR-U4-23 | 오늘보다 뒤의 날짜는 고를 수 없다 |

### 3.2 사는 곳 (Q3=A)

| ID | 규칙 |
|---|---|
| BR-U4-25 | 시도 16개를 목록으로 고른다(2026년 광주·전남 통합 반영 — "광주·전남" 하나). **서울·경기·인천**을 고르면 시군구 목록(서울 25구, 경기 31시군, 인천 11군구 — 2026-07 개편: 제물포·영종·서해·검단구)을 이어서 고른다. 다른 시도는 시도까지만 (`sigungu: null`) |
| BR-U4-26 | 저장 형식: `sido`는 줄임 이름("경기", U2 `normalizeSido`), `sigungu`는 "하남시"·"강남구"처럼 목록 이름 그대로 |
| BR-U4-27 | 직접 타이핑은 없다. [잘 모르겠어요]는 없다 (사는 곳은 누구나 안다) — 단 [다음]은 시도를 골라야 눌린다. 서울·경기·인천에서 시군구를 안 고르면 [다음]을 누를 수 없다 |

### 3.3 기간 구간 (Q4=A)

구간을 고르고, 판정에는 **구간의 아래 값**을 저장한다.

| 항목 | 구간 → 저장 값 |
|---|---|
| 거주 기간 `residence.years` (년) | 1년 미만 → 0 · 1~2년 → 1 · 2~3년 → 2 · 3~5년 → 3 · 5~10년 → 5 · 10년 이상 → 10 |
| 무주택 기간 `housing.homelessYears` (년) | 1년 미만 → 0 · 1~2년 → 1 · 2~3년 → 2 · 3~5년 → 3 · 5~10년 → 5 · 10~15년 → 10 · 15년 이상 → 15 |
| 통장 가입 기간 `savings.months` (개월) | 6개월 미만 → 0 · 6개월~1년 → 6 · 1~2년 → 12 · 2~5년 → 24 · 5~10년 → 60 · 10년 이상 → 120 |

| ID | 규칙 |
|---|---|
| BR-U4-30 | 저장 값 → 구간은 "저장 값 이하인 가장 큰 아래 값"의 구간이다 (고치기 화면에서 다시 보여 줄 때). 구간 → 값 → 구간은 같은 구간 |
| BR-U4-31 | 아래 값을 쓰는 이유: "2년 이상" 조건에서 2~3년을 고른 분은 충족, 1~2년은 미충족으로 **과대 판정하지 않는다** (경계에서 실제보다 짧게 잡음) |
| BR-U4-32 | 납입 횟수 `paymentCount`는 숫자 고르기(0~600회) + [잘 모르겠어요] |
| BR-U4-33 | 세 기간 모두 [잘 모르겠어요] → `null` |

### 3.4 금액 (US-06, Q5=A)

| ID | 규칙 |
|---|---|
| BR-U4-40 | **만원 단위** 숫자 키패드 입력. 0 이상 정수만 (쉼표·소수점 입력 안 됨) |
| BR-U4-41 | 입력하는 동안 아래에 한글 금액을 크게: 0 → "0원", 350 → "350만원", 12,000 → "1억 2,000만원", 100,000 → "10억원". 월 소득은 앞에 "월 " |
| BR-U4-42 | **단위 실수 확인**: 아래 값을 **넘으면** [다음]을 누를 때 "입력하신 금액이 **{한글 금액}** 맞나요?" 창 → [맞아요] / [다시 입력]. [맞아요]면 그대로 저장. 같은 값으로 다시 묻지 않는다 |
| BR-U4-43 | 확인 기준: 월 소득 **2,000만원**, 총자산 **300,000만원(30억원)**, 자동차 **10,000만원(1억원)**, 통장 금액 **10,000만원(1억원)** |
| BR-U4-44 | 상한 **1,000,000만원(100억원)** 초과는 저장할 수 없다 (U2 BR-U2-72): "금액이 너무 커요. 만원 단위로 넣었는지 확인해 주세요" |
| BR-U4-45 | 각 금액 화면에 한 줄 설명(무엇을 넣는지)과 "이 정보는 자격 확인에만 쓰이고, 암호화해서 저장해요"를 보여 준다 |
| BR-U4-46 | 금액 화면마다 [잘 모르겠어요] → `null` (→ 소득·자산 조건 "확인 필요") |

### 3.5 필수 항목·잘 모르겠어요 (Q6=A)

| ID | 규칙 |
|---|---|
| BR-U4-50 | **필수**: 본인 생년월일(화면 1), 세대 구성(화면 2), 관심 지구 1곳 이상(화면 20), 사는 곳 시도(화면 6). 필수 화면에는 [잘 모르겠어요]가 없고, 답이 없으면 [다음]이 눌리지 않는다 |
| BR-U4-51 | 화면 3의 가족 수·배우자 유무는 `other`를 고르면 필수 (판정의 세대원 수에 필요) |
| BR-U4-52 | 나머지 화면은 모두 [잘 모르겠어요]가 있고, 누르면 그 화면 항목을 `null`로 두고 다음 화면으로 간다. 단 **선호 화면(넓이·분양/임대·저층)에는 없다** — 처음부터 기본값(넓이 "상관없음", "둘 다", 저층 "상관없음")이 있어서 [다음]만 누르면 된다 (코드 생성 때 보완) |
| BR-U4-53 | 지구를 하나도 고르지 않고 [다음]을 누르면 "한 곳 이상 골라 주세요"를 보여 준다 |
| BR-U4-54 | 확인 화면에서 비워 둔(`null`) 항목이 하나라도 있으면 "비워 둔 항목은 '확인 필요'로 표시돼요"를 보여 준다 |
| BR-U4-55 | 마법사가 만든 프로필은 **항상 U2 `validateProfile`을 통과한다** (필수가 채워진 모든 답 조합에서) |

## 4. 저장·동기화 (US-08·18, Q7=A·Q8=A)

| ID | 규칙 |
|---|---|
| BR-U4-60 | 기기에는 프로필을 **암호화하지 않고** 저장한다(Q7=A). 휴대폰 잠금과 브라우저의 사이트별 분리가 보호한다. 서버에는 U2 코덱으로 금액만 암호화해 저장한다 |
| BR-U4-61 | **기기가 원본**이다. 서버 프로필은 판정·알림을 위한 사본이고, 서버에서 기기로 프로필을 내려받지 않는다 (기기 간 동기화 없음 — requirements 범위 밖) |
| BR-U4-62 | [저장] 순서: ① 기기에 저장(`profile`·`savedAt`, 동기화 상태 `pending`) ② 초안 삭제 ③ `PUT /api/profile` ④ 성공 → `synced`, "저장했어요" |
| BR-U4-63 | 서버 저장이 **네트워크 오류·5xx**로 실패하면 기기 저장은 그대로 두고 "인터넷 연결을 확인해 주세요. 다음에 앱을 열 때 다시 보낼게요"를 보여 준 뒤 계속 진행한다(알림 단계, 또는 저장 결과 화면의 [맞춤 공고 보러 가기]로 피드에) |
