# U2 eligibility-engine — 비기능 요구사항

> 근거: U2 NFR 계획 답변 (Q1=A 서버 사유에 내 금액 미저장, Q2=A 실제 공고 골든 세트, Q3=B 기준표 갱신 알림 없음, Q4=A 키 교체 절차서)
> U1 NFR(NFR-U1-01~29)은 공통 기반으로 그대로 적용한다. 여기서는 U2에 추가되는 요구사항만 적는다.

---

## 1. 성능

| ID | 요구사항 | 근거 |
|---|---|---|
| NFR-U2-01 | 공고 1건 판정(`judgeNotice`, 주택형 ≤ 20개) **1ms 이하** (Node 24 기준) | 순수 계산 |
| NFR-U2-02 | 기기 1대 전체 재계산(공고 ≤ 2,000건) **1초 이하** (DB 읽기·쓰기 포함, 서울 리전). U4 프로필 저장 API 응답(p95 < 500ms, NFR-U1-03)에서 재계산이 이 시간을 넘으면 저장 응답 뒤로 미루는 방식을 U4에서 검토 | US-18 "판정이 바로 바뀐다" |
| NFR-U2-03 | 전체 재계산(기기 ≤ 10) **10초 이하**. Edge Function 실행 제한 안 | U3 수집 직후 실행 |
| NFR-U2-04 | 기준 데이터(지구·기준표·표준 요건)는 재계산 1회당 1번만 읽는다 (BR-U2-81) | |

## 2. 신뢰성 · 정확성

| ID | 요구사항 |
|---|---|
| NFR-U2-05 | 기기 1대의 복호화·판정 실패는 그 기기의 기존 판정을 유지하고 다른 기기에 영향을 주지 않는다 (BR-U2-82) |
| NFR-U2-06 | 판정은 결정적이다: 같은 프로필·공고·기준 데이터·asOf → 같은 결과 (`computedAt` 제외) |
| NFR-U2-07 | **실제 공고 골든 세트 (Q2=A)**: U3 수집이 시작되면 3기 신도시 실제 공고 **5~10건**(행복주택·국민임대·통합공공임대·공공분양·민영 포함)을 골라, 사람이 공고문을 보고 정한 판정을 예시 테스트로 고정한다. 규칙·시드를 바꿀 때 이 테스트가 모두 통과해야 한다. **작업 위치: U3 Code Generation 마지막 단계** (공고 원문 데이터가 필요) |
| NFR-U2-08 | 골든 세트의 공고 데이터는 공개 공고 정보만 쓰고, 테스트용 가구 프로필은 가상의 값으로 만든다 (실제 가족 정보 금지, NFR-2.6) |
| NFR-U2-09 | "놓치지 않기" 불변식(BR-U2-33: 정보 부족·애매함은 절대 미충족을 만들지 않음)은 PBT로 항상 검증한다 |

## 3. 보안 · 개인정보

| ID | 요구사항 |
|---|---|
| NFR-U2-10 | **서버 사유에 내 금액 미저장 (Q1=A)**: `judgements.detail`에 저장하는 사유 문구에는 **기준 금액만** 넣고, 프로필의 소득·총자산·자동차 금액은 넣지 않는다. 화면(U5)은 기기의 프로필로 "→ 월 450만원"을 붙여 보여준다. 이를 위해 판정 결과에 어떤 프로필 값을 붙일지 알려 주는 `userValue` 키(`monthlyIncome` / `totalAsset` / `carValue`)를 둔다 |
| NFR-U2-11 | 위 규칙은 PBT로 검증한다: 임의 프로필로 판정한 결과의 사유·행동 문구 어디에도 그 프로필의 금액(만원 숫자, 원 환산 숫자, "○○만원" 표기)이 나오지 않는다 |
| NFR-U2-12 | 복호화한 금액은 판정 계산 동안 메모리에만 두고, 로그·오류 메시지·DB에 남기지 않는다. 복호화 오류 메시지에는 기기 ID 앞 8자리와 키 버전만 남긴다 |
| NFR-U2-13 | 생년월일·거주지 등 금액이 아닌 프로필 항목은 U1 설계대로 `device_profiles.data`에 평문(JSON)이다. 판정 사유에 나이("만 66세인 분")가 들어가는 것은 허용한다 (금액만 암호화 대상, NFR-2.3) |
| NFR-U2-14 | **키 교체 (Q4=A)**: 자동 재암호화는 만들지 않는다. 절차서(`docs`)와 확인용 SQL(옛 키 버전 암호문 수 세기)을 제공한다. 옛 키는 그 수가 0이 된 뒤에만 삭제한다. 교체 중에는 옛 키와 새 키를 함께 등록해 둔다 (NFR-U1-15) |
| NFR-U2-15 | 금액 입력 범위: 0 이상 정수, 상한 1,000,000만원 (BR-U2-72). 범위 밖이면 저장 전 거부 |

## 4. 유지보수성

| ID | 요구사항 |
|---|---|
| NFR-U2-16 | 판정 규칙 코드는 규칙 ID(BR-U2-xx)를 주석으로 단다. 규칙 ↔ 테스트 추적이 가능해야 한다 |
| NFR-U2-17 | `_shared`는 npm·Deno·Node 전용 API를 쓰지 않는다 (U1 규칙 유지). WebCrypto만 예외 |
| NFR-U2-18 | **기준표 갱신 (Q3=B)**: 자동 알림은 두지 않는다. 개발자가 매년 1~3월 도시근로자 월평균소득·기준 중위소득 공식표를 확인해 시드 마이그레이션으로 추가한다. 절차는 README의 "연간 갱신" 절에 적는다 |
| NFR-U2-19 | 공급유형 표준 요건 값은 마이그레이션 SQL에 **출처 URL과 확인 날짜를 주석**으로 남긴다 |
| NFR-U2-20 | 사유·행동 문구는 한 파일(`eligibility/messages.ts`)에 모아 쉬운 말 점검·수정이 쉽게 한다 (NFR-1.3) |
