# U2 eligibility-engine — 비즈니스 규칙

> 원칙: **놓치지 않기** (Q6=A). 값을 모르거나 기준이 애매하면 "미충족"이 아니라 "확인 필요"로 판정한다.
> 규칙 ID는 테스트·코드 주석에서 참조한다.

---

## 1. 지구 매칭 (C2, FR-2)

| ID | 규칙 |
|---|---|
| BR-U2-01 | 매칭 대상 텍스트 = 공고명 + 단지명 + 공급위치. 비교 전에 유니코드 NFC 정규화, 공백 제거 |
| BR-U2-02 | 지구의 `keywords` 중 하나가 텍스트에 있으면 그 지구로 매칭 |
| BR-U2-03 | 지구의 `sigungu` 중 하나가 텍스트(또는 공고의 시군구 필드)에 있고, **동시에** `area_keywords` 중 하나가 있으면 매칭 |
| BR-U2-04 | 시군구만 맞고 키워드가 없으면 매칭하지 않음 (예: 하남시 미사 공고는 교산이 아님) |
| BR-U2-05 | 하나의 공고가 여러 지구에 매칭될 수 있다 (FR-2.5). 결과는 지구 `sortOrder` 순, 중복 없음 |
| BR-U2-06 | 비활성(`active=false`) 지구는 매칭하지 않는다 |
| BR-U2-07 | (U3 Step 12 실제 공고로 추가) BR-U2-03 동 키워드 매칭은 **보조 규칙**: 어떤 지구든 BR-U2-02 대표 키워드로 매칭됐거나, 텍스트에 `지구`가 있으면(다른 이름의 지구를 밝힌 공고) 쓰지 않는다. 예: 인천계양 공고의 지구 경계 설명에 "부천시 대장동"이 나열됨 → 계양만, "남양주진접2지구"(진접읍) → 왕숙 아님 |

## 2. 공급유형 분류 (C3, FR-3)

원천 공급유형 문자열(주택형·공고 구분)과 공고명을 합친 텍스트에서 **위에서부터** 처음 맞는 규칙을 쓴다.

| ID | 순서 | 포함 단어 | 코드 |
|---|---|---|---|
| BR-U2-10 | 1 | 무순위, 잔여세대, 계약취소, 취소후재공급 | `unranked` |
| BR-U2-11 | 2 | 고령자복지주택 | `senior_welfare` |
| BR-U2-12 | 3 | 영구임대 | `permanent_rental_senior` |
| BR-U2-13 | 4 | 국민임대 | `national_rental_senior` |
| BR-U2-14 | 5 | 행복주택 | `happy_senior` |
| BR-U2-15 | 6 | 통합공공임대 | `integrated_rental` |
| BR-U2-16 | 7 | 공공분양, 국민주택, 뉴:홈, 뉴홈, 나눔형, 선택형, 일반형 | `public_sale_general` |
| BR-U2-17 | 8 | 민영, (소스가 청약홈이고 위에 해당 없음) | `private_sale_general` |
| BR-U2-18 | 9 | 그 밖 | `other` |

- BR-U2-19: 분류는 결정적(같은 입력 → 같은 결과)이고 모든 입력에 대해 코드 하나를 낸다
- BR-U2-19a: 행복주택 공고는 계층(청년·신혼·고령자)이 섞여 있어도 `happy_senior`로 분류한다. 이 앱 사용자에게 의미 있는 것은 고령자 계층뿐이다

## 3. 요건 확정 (C4, AD-7 + Q4=A)

표준 요건 S(공급유형별 시드)와 공고에서 AI가 추출해 **형식 검증을 통과한** 요건 E를 조건별로 합친다.

| ID | 경우 | 결과 |
|---|---|---|
| BR-U2-20 | E가 없음(추출 실패·미실행) | S |
| BR-U2-21 | 조건이 S에만 있음 | S의 값 (추출에서 빠졌다고 조건이 없다고 보지 않음) |
| BR-U2-22 | 조건이 E에만 있음 | E의 값 (공고가 조건을 추가) |
| BR-U2-23 | **구조 조건**(나이 기준, 무주택 필요, 거주 지역, 세대주, 복지)이 S·E 둘 다 있고 같음 | 그 값 |
| BR-U2-24 | 구조 조건이 S·E에서 다름 | `"unknown"` (분류가 틀렸을 수 있음) |
| BR-U2-25 | **금액·기간 조건**(소득 금액·비율, 총자산, 자동차, 통장 기간·횟수·예치금)이 둘 다 있음 | **E** (공고가 최종 기준, Q4=A). 단 E가 S의 0.5배~2배를 벗어나면 추출 오류로 보고 `"unknown"` |
| BR-U2-26 | S가 `"unknown"`이고 E에 값이 있음 | E |
| BR-U2-27 | E가 `"unknown"` | `"unknown"` |
| BR-U2-28 | S가 `unclassified`인데 E가 있음 | E만 사용 (분류 실패를 추출로 보완). E도 없으면 `unclassified` 유지 |

> AD-7("둘이 다르면 확인 필요")을 Q4=A에 맞게 다듬었다: 금액은 공고 값을 쓰고, 나머지 구조 조건이 다를 때만 확인 필요로 둔다.

## 4. 조건별 판정 (C5)

### 4.1 공통

| ID | 규칙 |
|---|---|
| BR-U2-30 | 조건 키가 없으면 판정하지 않는다 (결과 목록에 넣지 않음) |
| BR-U2-31 | 조건이 `"unknown"`이면 → **unknown**, 사유 "공고마다 기준이 달라요", 행동 "원문의 '신청 자격'을 확인해 주세요" |
| BR-U2-32 | 판정에 필요한 프로필 값이 `null`이면 → **unknown**, 행동 "설정에서 ○○을 입력하면 정확히 알려 드려요" |
| BR-U2-33 | **unknown은 절대 ineligible을 만들지 않는다**: 정보가 부족해서 미충족이 되는 경로는 없다 |
| BR-U2-34 | 기준 값의 출처가 서로 다를 때는 더 너그러운 값을 시드로 쓴다 (domain-entities §5.3) |

### 4.2 나이 (Q1=A 가구 단위, Q2=A 모집공고일)

| ID | 규칙 |
|---|---|
| BR-U2-35 | 기준일 = 모집공고일 ?? 접수 시작일 ?? 판정 날짜(한국 날짜) |
| BR-U2-36 | 만 나이 = 기준일 연도 − 출생 연도, 기준일이 생일 전이면 −1. 2월 29일생은 평년에는 3월 1일에 나이가 든다 |
| BR-U2-37 | `who: "member"` → 본인·배우자 중 **한 분이라도** `minAge` 이상이면 eligible. 둘 다 미만이면 ineligible. 판단할 수 없는 사람(생년월일 null)이 있고 아는 사람은 모두 미만이면 unknown |
| BR-U2-38 | `who: "head"` 또는 세대주 조건(`household.headRequired`)과 나이 조건이 함께 있으면 **세대주의 나이**로만 판단. 세대주가 `other`면 ineligible(부부 중 세대주가 아님), `null`이면 unknown |
| BR-U2-39 | 사유 예: "만 65세 이상 → 두 분 중 만 66세인 분이 있어요" / "만 65세 이상 → 두 분 모두 아직 만 64세 이하예요" |

### 4.3 무주택

| ID | 규칙 |
|---|---|
| BR-U2-40 | `homeless` true → eligible, false → ineligible, null → unknown |
| BR-U2-41 | `minYears`가 있으면 `homelessYears ≥ minYears`도 확인 (null → unknown) |

### 4.4 소득 (Q4=A)

| ID | 규칙 |
|---|---|
| BR-U2-42 | 적용 비율 = `percentBySize[가구원수]` ?? `percent`. 배우자 소득이 있고(`spouseEarns=true`) `dualIncomePercent`가 있으면 그 비율 |
| BR-U2-43 | 기준 금액(원) = 공고 금액 `amountsWon[가구원수]`가 있으면 그 값, 없으면 기준표(공고 연도, basis, 가구원수)의 100% × 비율 / 100 반올림. 공고 연도 = 모집공고일 ?? 접수 시작일 ?? 판정일의 연도 |
| BR-U2-44 | 기준표에 그 연도·가구원수가 없으면 → unknown, 행동 "올해 소득 기준표가 아직 준비되지 않았어요. 공고문의 소득 기준을 확인해 주세요" |
| BR-U2-45 | 세대 월소득(만원 × 10,000) ≤ 기준 금액 → eligible, 초과 → ineligible. 소득 null → unknown. `spouseEarns`가 null이고 단독 기준은 넘지만 맞벌이 기준 이하면 → unknown |
| BR-U2-45a | `appliesToAreaMaxM2`가 있고 주택형 면적이 그보다 크면 소득 조건을 적용하지 않는다. 면적을 모르면 소득 판정을 하되, 결과가 ineligible이면 **unknown**으로 바꾼다 (면적을 몰라서 미충족이 되면 BR-U2-33 위반) |

### 4.5 청약통장

| ID | 규칙 |
|---|---|
| BR-U2-46 | 민영 예치금 기준(`private_by_region_area`, 주택공급에 관한 규칙 별표2, 만원): 서울·부산 300/600/1000/1500, 그 밖의 광역시(인천·대구·광주·대전·울산) 250/400/700/1000, 그 밖의 시·군(경기 등) 200/300/400/500 — 각각 전용 85㎡ 이하 / 102㎡ 이하 / 135㎡ 이하 / 그 초과. 지역은 **신청자 거주지**(프로필 `residence.sido`) |
| BR-U2-47 | `has` false → ineligible, null → unknown. `months < minMonths` → ineligible, `paymentCount < minPayments` → ineligible, 예치금 미달 → ineligible. 비교에 필요한 값이 null이면 unknown |
| BR-U2-48 | 주택형 면적을 모르면 예치금은 가장 낮은 구간(85㎡ 이하)으로 비교하되, 그 구간은 넘고 더 높은 구간은 못 넘으면 unknown |

### 4.6 자산·자동차·거주·세대주·복지

| ID | 규칙 |
|---|---|
| BR-U2-50 | 총자산 ≤ `maxManwon` → eligible, 초과 → ineligible, null → unknown. 자동차도 같은 방식 |
| BR-U2-51 | 거주: `residence.sido`가 `sidoIn` 안에 있으면 eligible, 밖이면 ineligible, null → unknown. 시도 이름은 "서울/서울특별시"처럼 줄임·정식 명칭을 같게 본다 |
| BR-U2-52 | 세대주: `headRequired`이면 세대주가 `self`·`spouse` → eligible, `other` → ineligible, null → unknown |
| BR-U2-53 | 복지: `welfare`가 `anyOf`에 있으면 eligible. 아니면 `orIncome`이 있을 때 소득 판정(BR-U2-42~45)을 대신 적용. `welfare`가 `none`이고 `orIncome`도 없으면 ineligible. `welfare`가 null이면, `orIncome` 판정이 eligible이면 eligible, 아니면 unknown |
| BR-U2-54 | `welfare`가 `other_priority`(국가유공자·장애인 등)면, anyOf에 없더라도 **unknown** (이 앱이 세부 자격을 다루지 않음, 놓치지 않기) |

## 5. 합성 (주택형 → 공고) · 노출

| ID | 규칙 |
|---|---|
| BR-U2-55 | 주택형 판정: 조건 중 하나라도 ineligible → ineligible, 아니면 하나라도 unknown → unknown, 아니면 eligible. 조건이 하나도 없으면 eligible |
| BR-U2-56 | `unclassified` 주택형 → unknown, 사유 "공급유형을 알 수 없어요" |
| BR-U2-57 | 공고 판정: 주택형 중 하나라도 eligible → eligible, 아니면 하나라도 unknown → unknown, 아니면 ineligible. 주택형이 0개면 unknown |
| BR-U2-58 | `inDistrict` = 공고 지구 ∩ 관심 지구 ≠ ∅ |
| BR-U2-59 | **노출 조건 K5** (피드·알림 공통): `verdict ≠ ineligible` **그리고** `inDistrict` **그리고** 공고 상태 ≠ closed (U1 `noticeStatus`) |

## 6. 추천 점수 · 정렬 (Q5=A, Q6=B)

| ID | 규칙 |
|---|---|
| BR-U2-60 | 면적 구간: `xs` ≤ 40㎡, `s` 40 초과~60 이하, `m` 60 초과~85 이하, `l` 85 초과. 모든 면적은 정확히 한 구간에 속한다 |
| BR-U2-61 | 면적 일치(0/1): 관심 구간이 0개면 1, 아니면 주택형 중 하나라도 면적이 관심 구간에 들면 1 |
| BR-U2-62 | 분양/임대 일치(0/1): `both`면 1, 아니면 공고 `tenure`가 같으면 1 |
| BR-U2-63 | 저층 선호는 공고에 층 정보가 없어 1차에서는 점수에 넣지 않는다 (OI-U2-2) |
| BR-U2-64 | `score` = 면적 일치 + 분양/임대 일치 (0~2). 점수는 **정렬만** 바꾸고 숨기지 않는다 |
| BR-U2-65 | 정렬(U5·피드): ① 접수 중 → 접수 예정 ② **score 높은 순** (Q6=B) ③ 마감일 빠른 순(없으면 뒤) ④ eligible → unknown ⑤ 첫 수집이 최근인 순 ⑥ 공고 ID (항상 같은 순서가 되게) |

## 7. 암호화 · 코덱 (C7, C8)

| ID | 규칙 |
|---|---|
| BR-U2-70 | AES-256-GCM, IV 12바이트 무작위, 평문은 금액 10진 문자열. 같은 금액도 매번 다른 암호문 |

| BR-U2-72 | 금액은 0 이상 정수(만원), 상한 1,000,000(100억원). 범위 밖은 저장 전에 거부 |
| BR-U2-73 | 코덱 `decode(encode(p)) = p`. `schemaVersion`이 1이 아니면 decode 오류 |

## 8. 재계산 서비스 (S2)

| ID | 규칙 |
|---|---|
| BR-U2-80 | `recomputeForDevice`: 그 기기 프로필 × **보관 중인 모든 공고**를 판정하고 판정을 통째로 교체 (마감 공고도 상세 화면의 판정 사유용으로 계산) |
| BR-U2-81 | `recomputeAll`: 프로필이 있는 모든 기기에 대해 BR-U2-80. 기준 데이터는 실행당 1번만 읽는다 |
| BR-U2-82 | 한 기기의 복호화·판정이 실패하면 그 기기는 **기존 판정을 그대로 두고** 건너뛰며, 실패를 기록한다. 다른 기기는 계속 |
| BR-U2-83 | 판정 날짜(asOf)는 실행 시점의 한국 날짜. 같은 입력·같은 asOf면 같은 결과(`computedAt` 제외) |
| BR-U2-84 | 프로필이 없는 기기는 판정을 만들지 않는다 (피드는 U4 시작 안내) |

| ID | 규칙 |
