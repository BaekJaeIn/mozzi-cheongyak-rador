# U3 collection-pipeline — 비기능 요구사항

> 근거: U3 NFR 계획 답변 (Q1=A AI 처리를 별도 `analyze` 함수로 매시간, Q2=A 요청 단위 1회 재시도) + 계획에서 정한 항목 5개
> U1·U2 NFR은 공통 기반으로 그대로 적용한다.

---

## 1. 실행 구조 (Q1=A) — 기능 설계 변경

| 함수 | 주기 | 하는 일 | 시간 목표 |
|---|---|---|---|
| `collect` | 매일 1회 | 수집 → 정규화 → 지구 매칭 → 묶기 → 저장 (AI가 필요한 공고는 `summary_status = pending`) → 전체 판정 재계산(표준 요건으로) | **90초 이내** |
| `analyze` | **매시간** | `pending`(그리고 `failed`이면서 시도 3회 미만) 공고를 **최대 2건** 골라 PDF 추출·요약 → 묶음 저장 → 처리한 공고가 있으면 전체 판정 재계산 | **120초 이내** |

- 기능 설계 BR-U3-52·53·67의 "AI 다시 하기·상한"은 `analyze`가 맡는다. `collect`는 AI를 부르지 않는다
- 공고 20건이 한꺼번에 생겨도 10시간 안에 모두 처리된다 (2건 × 10회)
- 처리 순서: 접수 마감이 가까운 공고 → 먼저 수집된 공고 (마감 전에 정밀 판정이 나오게)
- `analyze`는 U6 `dispatch`(매시 정각)와 겹치지 않는 시각(예: 매시 30분)에 돈다 — 시각은 Infrastructure Design

## 2. 성능·시간 예산

| ID | 요구사항 |
|---|---|
| NFR-U3-01 | `collect` 전체 90초 이내 (Edge Function 벽시계 한도 안에서 여유). 소스별 시간 상한: 청약홈 20초, LH(목록+상세) 40초, GH 10초 — 넘으면 그 소스는 그때까지 모은 것만 처리하고 경고 |
| NFR-U3-02 | LH 상세 조회 동시 4건, 요청마다 시간 제한 10초 |
| NFR-U3-03 | `analyze`: PDF 내려받기 20초·20MB 상한, Gemini 호출 60초 제한. 시작 후 70초가 지나면 두 번째 공고를 시작하지 않는다 |
| NFR-U3-04 | 전체 판정 재계산은 U2 목표(NFR-U2-03, 10초) 안 |
| NFR-U3-05 | 메모리: PDF는 한 번에 1개만 메모리에 둔다 (256MB 한도) |

## 3. 신뢰성

| ID | 요구사항 |
|---|---|
| NFR-U3-06 | **요청 재시도 (Q2=A)**: 네트워크 오류·HTTP 5xx·429면 2초 뒤 1번 다시 요청. 그래도 실패하면 그 소스(목록) 또는 그 공고(상세·PDF)만 건너뛰고 기록 |
| NFR-U3-07 | 소스 실패 격리(BR-U3-01), 공고 1건 저장 실패 격리(트랜잭션 단위) |
| NFR-U3-08 | 재실행 안전: `collect`·`analyze`를 같은 날 여러 번 실행해도 중복 저장·중복 AI 호출이 없다 (해시·상태로 판단, BR-U3-51) |
| NFR-U3-09 | `analyze` 두 개가 동시에 돌아도 같은 공고를 두 번 처리하지 않는다 (공고를 고를 때 DB에서 잠금·표시) — 설계는 NFR Design |
| NFR-U3-10 | Gemini 응답이 잘리거나(JSON 불완전) 형식이 틀리면 실패로 처리하고 재시도 횟수를 센다 (사고 토큰이 출력 예산을 먹는 문제: 출력 토큰 상한을 넉넉히, 사고 예산 제한 — cheongYak-radar 경험) |

## 4. 보안·개인정보

| ID | 요구사항 |
|---|---|
| NFR-U3-11 | `collect`·`analyze`는 **서버 키(Authorization)가 맞는 호출만** 받는다. pg_cron이 Vault의 키로 호출 |
| NFR-U3-12 | Gemini에는 공고 PDF·제목·공급유형 후보만 보낸다. 가족 정보·프로필은 보내지 않는다 (FR-4.5). 무료 등급 데이터 정책을 감안해도 공개 정보만이라 허용 |
| NFR-U3-13 | data.go.kr 키는 URL 쿼리에 들어가므로 오류·로그·`collect_runs`에 요청 URL을 남기지 않는다 (BR-U3-72). Gemini 키는 헤더로만 |
| NFR-U3-14 | PDF 내용은 지시가 아닌 자료로 다룬다고 프롬프트에 명시하고, 응답은 정해진 JSON 스키마만 받는다. 스키마 밖 값은 버린다 (BR-U3-62·64) |
| NFR-U3-15 | PDF는 저장하지 않는다 (처리 후 버림). 주소만 `ai_source_url`에 남긴다 |
