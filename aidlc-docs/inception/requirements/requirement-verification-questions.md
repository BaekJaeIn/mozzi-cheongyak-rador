## Question: 복원력 확장 규칙 (Resiliency Extensions)
이 프로젝트에 복원력 기준선(resiliency baseline)을 적용할까요?

**이 확장은 무엇인가요?** 켜면 **AWS Well-Architected Framework(신뢰성 원칙)** 와 복원력 검토 지침에서 가져온 **설계 단계 모범 사례**를 적용합니다. 요구사항·설계·코드가 장애 허용, 고가용성, 관측성, 복구 가능성을 갖추도록 이끌며, 비즈니스 목표·변경 관리·관측성·고가용성·재해 복구·지속 개선에 걸친 15개 영역을 다룹니다.

**이 확장이 아닌 것:** 켠다고 해서 운영 준비가 끝나거나, 가용성·RTO(복구 목표 시간)·RPO(복구 목표 시점) 목표가 인증·보장되지는 **않습니다**. 좋은 복원력 결정을 일찍 잡아 주는 **출발점**일 뿐, 완성된 시스템에 대한 정식 **AWS Well-Architected Review**를 대신하지 않습니다.

결과물은 완성된 운영 인증 결과가 아니라, 이후 검증하고 보완해 나갈 **복원력 설계의 탄탄한 초안**으로 보시면 됩니다.

A) 예: 복원력 기준선을 방향성 있는 모범 사례·설계 지침으로 적용 (업무상 중요한 서비스에 권장. 출시 전에 검증·보강할 출발점)

B) 아니오: 복원력 기준선을 건너뜀 (빠른 반복이 신뢰성보다 중요한 PoC, 프로토타입, 실험 프로젝트에 적합)

X) 기타 (아래 [Answer]: 태그 뒤에 설명해 주세요)

[Answer]: B
